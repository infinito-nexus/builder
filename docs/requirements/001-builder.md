# 001 - Builder

## User Story

As a developer of an existing web application, I want to turn it into an Infinito.Nexus role from a few answers or from my `compose.yml`, locally through a CLI or on builder.infinito.nexus, so that I can deploy and operate it through the Infinito.Nexus framework without learning the role format by hand.

## Decisions

| # | Decision |
| --- | --- |
| 1 | Core owns the role contract. The role skeleton, its renderer, the manifest schema and a contract test that runs every rendered skeleton through core's `make test` and `make lint` live in core. The builder ships no role templates of its own. |
| 2 | The builder is the user-facing layer: the Python package `infinito-builder` (library and the `infinito-builder` command) and the site builder.infinito.nexus, which is built on the same library. |
| 3 | The builder renders with the renderer of a chosen core version. Core is not published on PyPI, so the builder fetches the tagged source archive of `infinito-nexus/core` and caches it per tag. Without a choice it uses the latest core release tag. A local core checkout may stand in for development. |
| 4 | The input is a manifest, `infinito-builder.yml`, filled either by the wizard (CLI prompts or the web form) or by importing a compose file. |
| 5 | The output is `ansible/roles/web-app-cst-<name>/` inside the application repository, the layout of `infinito-nexus/security`, plus the inventory snippet of core requirement 046 (`custom: true` and `source`). |
| 6 | In v1 the site renders from form selections only and returns a zip. It accepts no upload of source code or compose files; compose import is a CLI feature. |
| 7 | The site follows the design round result of 2026-11-11 23:55 (the Infinito Orrery language). Palette, font, radius and spacing come only from the `--design-*` tokens of core `web-svc-design`. Motion, logo variants and icons come from the brand role `web-app-cst-brand`, with the `builder blocks` motif for this site, and nav entries come from the brand config. The site renders its own header and footer on the server and lets the kit style them. The background is cosmos: the page includes `cosmos.js` and `cosmos-sky` gated on its cosmos service flag, clears its own background only under `html[data-cosmos-mode=full]`, and has no sky code of its own. The beaver comes from `infinito-nexus/avatar` into the header's avatar slot. |
| 8 | Once the CLI renders roles, the site itself runs as `web-app-cst-builder` from this repository, and that role is generated by the builder. The Production agent owns every deploy of it. |
| 9 | A generated role is a starting point, not a finished integration. It passes core's checks, and its README names the parts that need the developer's review: CSP, RBAC, application settings and Playwright specs beyond the baseline. |

## Acceptance Criteria

### Library and CLI

- [ ] `pip install infinito-builder` installs the library and the `infinito-builder` command on Python 3.11 or newer.
- [ ] `infinito-builder new` asks for the role name, the image with its tag, the HTTP port, the database (`postgres`, `mariadb`, `none`), the login (`oidc`, `ldap`, `none`) and the optional features (`email`, `redis`), writes `infinito-builder.yml` and renders the role.
- [ ] `infinito-builder new --manifest <file>` renders from an existing manifest without prompting.
- [ ] `infinito-builder import <compose-file>` writes a manifest from a compose file: the service that publishes an HTTP port becomes the application, a `postgres` or `mariadb` service becomes the database selection, and volumes and environment of the application service carry over.
- [ ] `infinito-builder import` lists every service it cannot map by name and never drops one silently.
- [ ] A manifest with a role name outside `[a-z0-9-]`, an image without a tag, or a port outside 1 to 65535 stops before rendering with a message naming the field.
- [ ] `--core <tag>` renders with that core release, `--core <path>` with a local core checkout; without the option the latest core release tag is used.
- [ ] A fetched core tag is cached under the user cache directory and not fetched again.
- [ ] The role lands at `ansible/roles/web-app-cst-<name>/` below the target directory, and an existing role directory is only replaced with `--force`.
- [ ] After rendering, the command prints the 046 inventory snippet for the role, with `source.url`, `source.version` and `source.path` filled from the target repository where Git knows them.
- [ ] `infinito-builder check` places the role into a core checkout and runs core's `make test` there; no other command runs it implicitly.
- [ ] The library exposes `manifest_from_compose`, `load_manifest` and `render` as the API the CLI and the site share.

### Site

- [ ] builder.infinito.nexus offers the wizard as a form with the same fields as the CLI and returns the rendered role, the manifest and the inventory snippet as one zip.
- [ ] The site has no file upload.
- [ ] The site uses the shared translation stack: its strings live in `locale/<code>/LC_MESSAGES/<domain>.po`, are translated through core `make i18n-translate` and the `web-svc-translate` gateway, and every language of core `meta/languages.yml` is served under `/<code>/` with `html` `lang` and `dir` and `hreflang` links.
- [ ] The site uses only `--design-*` tokens for color, font, radius and spacing and defines none of its own.
- [ ] The site links the CSS and SVG of `web-app-cst-brand`, shows the `builder blocks` motif and the shared icon sprite, and loads no icon font.
- [ ] Header and footer are rendered on the server, work without JavaScript, take their nav entries from the brand config, and keep one square avatar slot for the beaver.
- [ ] The site includes `cosmos.js` and `cosmos-sky` only while its cosmos service flag is on, contains no sky or starfield code, and clears its background only under `html[data-cosmos-mode=full]`.
- [ ] Text and controls meet WCAG 2.2 AA contrast against `--cosmos-sky-top` and against the `web-svc-design` background.
- [ ] The site runs as `web-app-cst-builder` from `ansible/roles/web-app-cst-builder/` in this repository, and that role was generated by `infinito-builder`.

### Quality

- [ ] Unit tests cover manifest validation, the compose import mapping including the list of unmapped services, and rendering against a local core checkout.
- [ ] CI renders a sample manifest against the latest core release, places the role into a core checkout and runs core's `make test` and `make lint` on it, limited to changes of the library or the sample.
